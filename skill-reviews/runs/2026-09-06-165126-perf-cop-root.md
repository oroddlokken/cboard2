## Performance Results

### Red — Fix Now
Unbounded growth, or user-facing cost on a path the evidence shows is hot.

1. [ ] **`RemoteReader._ancestry` grows without bound for the life of a TUI session** — a memoized `(family, local_sha, remote_sha)` dict is only trimmed when a whole family leaves the watch list; an actively-worked repo that stays behind and keeps advancing accumulates one entry per distinct sha-pair for as long as the dashboard runs.
   `src/cboard2/remote.py:911` (field), `:1220-1250` (`_behind`, writes the entry), `:1445-1455` (`forget_absent`, the only eviction) — cap with an LRU/bounded dict, or drop a family's entries when its `default_sha`/`branch_sha` changes instead of only on repo removal.
   Workload: `RemoteReader.refresh_local`, every 2s poll tick, multi-day dashboard session | Est. impact: removes the only genuine unbounded-growth pattern found in the codebase | Lens: `allocations` (flagged by 1/8)

2. [ ] **The 2s poll tick redoes a full git-subprocess batch every time, with no staleness gate and duplicated internal work** — `Board.refresh()` calls `Poller.poll`, `RemoteReader.refresh_local`, and `ActivityReader.prime` serially though none depends on another's result; inside `refresh_local`, `_checkouts` and `_ref_lines` each independently rebuild the same `leaders(repos)` dedupe set and each spins up its own short-lived `ThreadPoolExecutor` instead of one combined pass; and unlike `ActivityReader`'s mtime gate, `refresh_local` re-runs `for-each-ref`+`worktree list` even when nothing in the repo changed since the last tick.
   [CONFLICT] `caching-wins` says gate on `refs/heads`/`worktrees` mtime to skip unchanged families; `blocking` says run the three readers (and the two internal git calls) concurrently instead. Per the resolution ladder, removing the work beats speeding it up — gate first; run whatever survives the gate concurrently as a secondary improvement.
   `src/cboard2/board.py:99-124` (`Board.refresh`), `src/cboard2/remote.py:1073-1085` (`refresh_local`), `:1312` (`_checkouts`), `:1334` (`_ref_lines`), `:1437` (`_map`), `src/cboard2/gitstate.py:241`, `src/cboard2/activity.py:110` — add a cheap staleness check before the subprocess batch; dedupe the `leaders()` call; merge the two thread-pool passes into one; run the three readers concurrently.
   Workload: every 2s poll tick (`refresh_interval=2.0`, confirmed at `tui.py:848`), for the life of the dashboard, over the docstring-cited 75-109 repo reference scale | Est. impact: removes the single most frequently-repeated wasted-CPU pattern in the app — the whole hot loop | Lens: flagged by 4/8 (`caching-wins`, `blocking`, `io-batching`, `hot-loops`)

3.    `src/cboard2/remote.py:929-960` (`prime`), `src/cboard2/cli.py:59`, `src/cboard2/board.py:99-121` (`read_remote` then `refresh`) — reuse the already-fetched `lines`/`checkouts` (the pattern `read()` already uses at `remote.py:1011`) instead of calling `refresh_local()` again.
